# Companion README.md for the Git quickstart trip-ups notes

After writing the Git quickstart trip-ups notes (2026-07-13-git-quickstart-trip-ups.md), I needed a companion README.md that could sit alongside it and serve as a reference card. The trip-ups notes are written as a personal journal — "I got stuck on this" — but a README.md works better as a quick-scan reference, especially for someone who just wants the highlights without reading the full narrative.

## What I included

The README.md starts with a one-sentence summary of what the quickstart covers: installing Git, configuring identity, and understanding the staging area. Then I listed the five trip-ups I hit — staging vs committing, `git log` verbosity, branch creation vs switching, `git status` as a panic button, and the `-a` flag shortcut — each with a one-line description and a pointer to where the trip-ups notes explain the fix in detail.

## Where I got stuck

Drafting the README.md felt different from writing the trip-ups notes. The trip-ups notes are personal and messy; the README.md wants to be clean and scannable. I kept catching myself slipping into "I" voice and having to pull back. I also struggled with how much detail to include in each summary point — too little and it's useless, too much and it duplicates the trip-ups notes.

## What I'd try next

I'll compare the README.md side-by-side with the trip-ups notes and see whether someone can use the README.md alone or whether they always need to read both. If the README.md works standalone, it earns its place as a companion.
