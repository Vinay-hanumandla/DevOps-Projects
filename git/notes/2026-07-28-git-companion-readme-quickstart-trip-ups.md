# Companion README.md for the Git quickstart trip-ups notes

After writing the Git quickstart trip-ups notes (2026-07-15-git-quickstart-trip-ups.md), I needed a companion README.md that could sit alongside it and serve as a quick-reference card. The trip-ups notes are written as a personal journal — "I got stuck on this" — but a README.md works better as a scannable summary, especially for someone who wants the highlights without reading the full narrative.

## What I included

The README.md covers the five trip-ups from the quickstart notes: the staging area being an extra step, `git add` not meaning "saved," `git log` verbosity, `git branch` creating but not switching, and `git status` as a panic button. Each trip-up gets a one-line summary of the problem and the fix. I also added a "What I'd try next" section pointing toward branching and merging practice.

## Where I got stuck

Drafting the README.md felt different from writing the trip-ups notes. The trip-ups notes are personal and messy; the README.md wants to be clean and scannable. I kept catching myself slipping into "I" voice and having to pull back. I also struggled with how much detail to include in each summary point — too little and it's useless, too much and it duplicates the trip-ups notes. I settled on one sentence per trip-up for the problem and one for the fix.

## What I'd try next

I want to compare this README.md side-by-side with the trip-ups notes and see whether someone can use the README.md alone or whether they always need to read both. If the README.md works standalone, it earns its place as a companion. I also want to link it from the primer so newcomers can find it easily.
