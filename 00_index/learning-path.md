# Learning Path — DevOps

> A suggested progression from beginner to confident practitioner. Each stage builds on the previous one. If a topic is listed but has no content yet, it's marked as ⏳ (coming soon).

## Stage 1: Foundations

The concepts every DevOps task leans on. Each now has a first-day primer, and several have runnable companions.

- **Linux & CLI Fundamentals** — [primer](../docs/concepts/linux-cli-fundamentals/0000-primer-linux-cli-fundamentals.md): the shell, processes, and filesystem basics underpinning every tool here.
- **Version Control & Git Workflow** — [primer](../docs/concepts/version-control-git-workflow/0000-primer-version-control-git-workflow.md) for the ideas; then [Git quickstart trip-ups](../git/notes/2026-07-13-git-quickstart-trip-ups.md) and [Undo, stage, commit, push](../git/notes/2026-07-13-undo-stage-commit-push.md) for first contact. The [git workflow practice exercises script](../docs/concepts/version-control-git-workflow/scripts/2026-08-07-git-exercises.sh) gives read-only inspection practice for repo state, branch, and upstream tracking, and the [applying version control in DevOps snippet](../docs/concepts/version-control-git-workflow/snippets/2026-08-11-applying-version-control-in-devops.py) turns a branch's commit history into a release changelog. Once branches multiply, the [release-readiness commit inventory](../docs/concepts/version-control-git-workflow/snippets/2026-08-20-release-branch-commit-check.py) answers "is that fix shipped?" from the `release..main` range instead of from memory.
- **Containerization Concepts** — [primer](../docs/concepts/containerization-concepts/0000-primer-containerization-concepts.md) for what an image and container are; then [Docker quickstart trip-ups](../docker/notes/2026-07-13-docker-quickstart-trip-ups.md) to see it in practice. The [container lifecycle inspection](../docs/concepts/containerization-concepts/scripts/2026-07-20-container-lifecycle-inspection.sh) script and [image manifest parser](../docs/concepts/containerization-concepts/snippets/2026-07-22-image-manifest-parser.py) go deeper. Leads into [CI/CD Pipeline Concepts](../docs/concepts/ci-cd-pipeline-concepts/0000-primer-ci-cd-pipeline-concepts.md) and [Infrastructure as Code Principles](../docs/concepts/infrastructure-as-code-principles/0000-primer-infrastructure-as-code-principles.md).
- **Infrastructure as Code Principles** — [primer](../docs/concepts/infrastructure-as-code-principles/0000-primer-infrastructure-as-code-principles.md): describing infrastructure in files rather than by hand. Follow up with the [IaC idempotency check](../docs/concepts/infrastructure-as-code-principles/scripts/2026-07-22-iac-idempotency-check.sh) script and [declarative state diff](../docs/concepts/infrastructure-as-code-principles/snippets/2026-07-22-declarative-state-diff.py) snippet. The [parameterised config generation](../docs/concepts/infrastructure-as-code-principles/parameterised-config-generation.md) doc shows how one template plus a small parameter set produces every environment's config, and the [network topology Terraform script](../docs/concepts/infrastructure-as-code-principles/scripts/network-topology-terraform.sh) applies the same idea to a VPC and its subnets. Connects to [Containerization Concepts](../docs/concepts/containerization-concepts/0000-primer-containerization-concepts.md) and [CI/CD Pipeline Concepts](../docs/concepts/ci-cd-pipeline-concepts/0000-primer-ci-cd-pipeline-concepts.md).
- **Scripting & Automation Philosophy** — [primer](../docs/concepts/scripting-automation-philosophy/0000-primer-scripting-automation-philosophy.md): when to reach for a script instead of doing it manually. Then [scripting automation exercises](../docs/concepts/scripting-automation-philosophy/scripts/2026-08-07-scripting-automation-exercises.sh) for hands-on DRY/idempotency practice, the [applying scripting in DevOps snippet](../docs/concepts/scripting-automation-philosophy/snippets/2026-08-07-applying-scripting-in-devops.py) to see the habit in action, the [deploy checklist as data](../docs/concepts/scripting-automation-philosophy/snippets/2026-08-20-scripting-deploy-checklist.py) snippet that turns a known pre-deploy sequence into one list you loop over, and the [combining scripting with CI/CD pipeline automation](../docs/concepts/scripting-automation-philosophy/combining-scripting-with-cicd-pipeline-automation.md) guide, which pairs the philosophy with a plan-as-artifact [Terraform validate → plan → apply script](../docs/concepts/scripting-automation-philosophy/scripts/terraform-plan-apply-idempotent.sh).

## Stage 2: Core Tools

The tools unlocked from the start. Start here once the foundations make sense.

- **Git** — [Git primer](../git/notes/0000-primer-git.md), [quickstart trip-ups](../git/notes/2026-07-13-git-quickstart-trip-ups.md), and [undo/commit/push](../git/notes/2026-07-13-undo-stage-commit-push.md) cover first contact. [Install Git and first repo](../git/notes/2026-07-20-install-git.md) and [first-repo lifecycle script](../git/scripts/2026-07-20-first-repo.sh) give you a runnable first day. The [branch-merge-revert](../git/scripts/2026-07-20-branch-merge-revert.sh) script adds intermediate workflow practice. Then [feature branch rebase workflows](../git/scripts/feature-branch-rebase-workflow.sh), [Git hooks](../git/hooks/install.sh) and the [hook configuration notes](../git/docs/how-i-wired-git-hooks-into-my-local-dev-workflow.md), and the [interactive rebase guide](../git/docs/interactive-rebase-vs-merge-commit.md) take you deeper into history rewriting and automation. The [rebase vs merge at scale](../git/docs/rebase-vs-merge-at-scale.md) doc compares the two strategies once a repo crosses hundreds of contributors and long-lived release branches. The [Git PR helper](../git/scripts/git-pr-helper.sh) wraps branch-create, delete, clean-check, and PR-open in safety guards. For a catalogue of every Git file on disk, see [Git — my first file index](../git/docs/2026-08-10-git-index.md). Once you're comfortable with tags and branches, the [release-workflow project scaffold](../git/templates/release-workflow/README.md) shows one whole way to wire tag-driven releases end to end: copy it in, `make minor`, and it bumps `VERSION`, tags, and pushes. The [changelog-from-conventional-commits](../git/scripts/changelog-from-conventional-commits.sh) helper turns a conventional-commit history into a Markdown changelog by type. To see how the same repo events drive a build → test → deploy chain, the [CI/CD pipeline trigger manifest](../git/manifests/ci-cd-pipeline-trigger.yaml) maps push, tag, and merge-request events onto jobs with `workflow.rules`.
- **Docker** — [Docker primer](../docker/notes/0000-primer-docker.md), [quickstart trip-ups](../docker/notes/2026-07-13-docker-quickstart-trip-ups.md), [minimal non-root Dockerfile](../docker/dockerfiles/2026-07-17-minimal-image-tagged-nonroot.Dockerfile), [container run scripts](../docker/scripts/2026-07-18-first-port-mapped-container.sh), and the [sample apps](../docker/src/main.go) they build give you hands-on with images, port mapping, and multi-stage builds.
- **Bash** — [primer](../bash/notes/0000-primer-bash.md), [install and first script](../bash/notes/2026-07-18-install-bash-and-first-script.md), and a [hello-world script](../bash/scripts/2026-07-18-first-hello-world.sh) give you a first-day grounding. Then level up with the [trip-ups guide](../bash/notes/2026-07-23-bash-guide-trip-ups.md), [robust scripting patterns](../bash/docs/2026-07-23-robust-bash-scripts.md), [strict mode and trap patterns](../bash/docs/strict-mode-trap-patterns.md), the [debugging and profiling notes](../bash/docs/debug-and-profile-with-set-x-and-trace-traps.md), the [safe Bash template](../bash/scripts/2026-07-23-safe-bash-template.sh), the [system report tool](../bash/scripts/system-report-tool.sh), the companion scripts and tests, and the [comparing [ ] vs [[ ]] gotchas snippet](../bash/snippets/comparing-brackets-gotchas.sh). For a longer view, the [log-rotation notebook](../bash/notebooks/comparing-log-rotation-approaches.ipynb) weighs inotifywait against cron-driven polling, the [integrating Bash with Git doc](../bash/docs/integrating-bash-with-git.md) collects fail-fast, re-runnable release-script patterns, and the [Bash + Docker toolchain scaffold](../bash/templates/bash-docker-scaffold/README.md) shows how to keep the host clean by running shellcheck, shfmt, and bats inside a toolchain container. Once you're comfortable with containers, the [Bash + Docker health-check scaffold](../bash/templates/bash-docker-healthcheck-scaffold/README.md) is a copy-in stack (cache + web + worker) whose startup ordering is enforced by Docker health checks — both in Compose and inside the entry point. The [strict-mode runner Dockerfile](../bash/dockerfiles/strict-mode-runner.Dockerfile) packages that philosophy as a minimal image with `set -euo pipefail` and `set -x` baked in.
- **Python** — [primer](../python/notes/0000-primer-python.md), [create venv and run](../python/scripts/2026-07-22-create-venv-and-run.py), and [first script with variables and types](../python/snippets/2026-07-22-first-script-variables-types.py) give you a first-day grounding in scripting for ops tasks. Then [Python functions and modules](../python/notes/2026-08-04-python-functions-modules.md) covers function definitions, default arguments, and import patterns, while [Python modules, packages, and imports](../python/docs/2026-08-04-python-modules-packages-imports.md) explains import resolution and namespace packages. The [Python quickstart gotchas](../python/notes/2026-08-22-python-quickstart-gotchas.md) note covers first-contact pitfalls, the [minimal file processing script](../python/scripts/2026-08-04-minimal-file-processing.py) ties it together with a practical example, the [config file reader snippet](../python/snippets/2026-08-22-config-file-reader.py) shows how to read and parse config files, and the [config validator script](../python/scripts/config-validator.py) demonstrates Python configuration validation with type and port checks.
- **Kubernetes** — [Kubernetes primer](../k8s/notes/0000-primer-kubernetes.md), [Minikube install and kubectl version](../k8s/scripts/2026-08-03-install-minikube-and-run-kubectl-version.sh), and [kubectl exploration notes](../k8s/notes/2026-08-03-explore-kubectl-cli.md) give you hands-on with clusters, nodes, and kubectl. The [Kubernetes quickstart tripped up](../k8s/notes/2026-08-04-kubernetes-quickstart-tripped-up.md) note covers namespace confusion and Service exposure, while [inspecting pods, services, and events](../k8s/docs/2026-08-04-inspecting-pods-services-events.md) deepens your debugging toolkit. The [minimal deployment and service manifest](../k8s/manifests/2026-08-04-minimal-deployment-and-service.yaml) gives you a starting point for deploying workloads, the [first deployment config](../k8s/configs/2026-08-22-first-deployment.yaml) is a minimal nginx Deployment with resource requests and limits, and the [multi-service application manifest](../k8s/manifests/multi-service-application.yaml) shows a complete Deployment with frontend, backend, and Redis cache.

## Stage 3: Building Skills

Intermediate concepts that unlock more advanced tools.

- **CI/CD Pipeline Concepts** — [primer](../docs/concepts/ci-cd-pipeline-concepts/0000-primer-ci-cd-pipeline-concepts.md) for the ideas; [CI/CD stage simulation](../docs/concepts/ci-cd-pipeline-concepts/scripts/2026-07-19-pipeline-stage-sim.sh) is a pure-Bash pipeline to practice build→test→deploy gating, and the [artifact promotion snippet](../docs/concepts/ci-cd-pipeline-concepts/snippets/2026-07-20-artifact-promotion.py) shows how outputs move between stages. The [pipeline failure-detection script](../docs/concepts/ci-cd-pipeline-concepts/scripts/pipeline-failure-detection.sh) wraps a stage so transient failures retry and the reason is left as a parseable log record. The [infrastructure validation gates script](../docs/concepts/ci-cd-pipeline-concepts/scripts/infrastructure-validation-gates.sh) demonstrates how to wire Terraform and Ansible validation into a CI/CD pipeline as a gate that blocks deployment when configs are invalid. The [multi-stage build pipeline design](../docs/concepts/ci-cd-pipeline-concepts/multi-stage-build-pipeline-design.md) reference and the [gate-before-merge reference](../docs/concepts/ci-cd-pipeline-concepts/gate-before-merge-branch-protection.md) cover branch protection rules and status checks, and the [pipeline metrics and health dashboards notebook](../docs/concepts/ci-cd-pipeline-concepts/notebooks/pipeline-metrics-and-health-dashboards.ipynb) ties CI/CD to observability with DORA metrics. Builds on [Containerization Concepts](../docs/concepts/containerization-concepts/0000-primer-containerization-concepts.md) and [Infrastructure as Code Principles](../docs/concepts/infrastructure-as-code-principles/0000-primer-infrastructure-as-code-principles.md).
- **Networking Fundamentals** — [primer](../docs/concepts/networking-fundamentals/0000-primer-networking-fundamentals.md): ports, addresses, and how containers talk to each other and the host. The [combining networking with containerization](../docs/concepts/networking-fundamentals/combining-networking-with-containerization.md) guide extends these ideas to container networks. The [network connectivity check](../docs/concepts/networking-fundamentals/scripts/2026-07-25-practice-network-connectivity-dns-port-inspection.sh) lets you practice diagnosing reachability, the [networking observability health check](../docs/concepts/networking-fundamentals/scripts/networking-observability-health-check.sh) script adds service-health probing, and the [socket connection tester](../docs/concepts/networking-fundamentals/snippets/2026-07-26-socket-connection-tester.py) gives a Python companion. The [network interface and routing inspection](../docs/concepts/networking-fundamentals/scripts/2026-08-05-network-interface-and-routing-inspection.sh) script deepens your debugging toolkit. The [overlay networks and service mesh notebook](../docs/concepts/networking-fundamentals/notebooks/overlay-networks-and-service-mesh-exploration.ipynb) explores how overlay networks enable cross-host container communication and how service meshes add observability and traffic management. The [applying networking in DevOps snippet](../docs/concepts/networking-fundamentals/snippets/2026-08-23-applying-networking-in-devops.py) connects networking concepts to real DevOps tasks with TCP and HTTP endpoint checks.
- **Linux & CLI Fundamentals** — [primer](../docs/concepts/linux-cli-fundamentals/0000-primer-linux-cli-fundamentals.md): the shell, processes, and permissions. The [file permissions and processes](../docs/concepts/linux-cli-fundamentals/scripts/2026-07-24-linux-file-permissions-and-process-management.sh) script and [subprocess wrapper](../docs/concepts/linux-cli-fundamentals/snippets/2026-07-24-subprocess-wrapper.py) let you practice common sysadmin tasks. The [automating network diagnostics](../docs/concepts/linux-cli-fundamentals/combining-linux-cli-with-networking-automating-network-diagnostics.md) guide layers reachability, path, socket, and DNS probes into one scripted check, and the [provision local VMs with cloud-init](../docs/concepts/linux-cli-fundamentals/scripts/provision-local-vms-with-cloud-init.sh) script applies the same CLI discipline to declarative VM provisioning.
- **Containerization + Observability** — [primer](../docs/concepts/containerization-concepts/0000-primer-containerization-concepts.md) plus [monitoring containerized apps in production](../docs/concepts/containerization-concepts/monitoring-containerized-apps-in-production.md) cover instrumenting containers with metrics, logs, and traces so they're no longer black boxes. The [observability exercises](../docs/concepts/observability-monitoring-concepts/scripts/2026-08-06-observability-exercises.sh) and [RED-method snippet](../docs/concepts/observability-monitoring-concepts/snippets/2026-08-07-applying-observability-in-devops.py) give hands-on practice.

## Progression Map

Bash, Docker, Git, Helm, Jenkins, Kubernetes, Python, Terraform, GitHub Actions, Prometheus, and Grafana have tool content on disk today, and all eight foundational concepts now have primers. CI/CD, containerization, IaC, Linux & CLI, networking, scripting/automation, and observability concepts all have runnable scripts, snippets, and hands-on exercises — the newest networking addition is a network interface routing practice script, CI/CD gained an infrastructure validation gates script, and scripting gained a deploy checklist encoded as data. Ansible has a first-contact primer, install notes, and two playbook configs. The kit carries three project scaffolds: a Git release workflow under `git/`, and two Bash + Docker layouts under `bash/` — a toolchain container and a health-checked multi-container stack. Git also holds a pipeline-trigger manifest showing how push, tag, and merge-request events start build → test → deploy jobs, a doc comparing rebase vs merge at scale, and a helper that derives a changelog from conventional commits. IaC has a parameterised config generation doc and a network-topology Terraform script. Helm has a package-manager install note, a quickstart walk-through, and dev/staging/prod values overrides for one chart. The rest of the map shows what unlocks what once the tool notes land.

```
Foundations (Linux, Git workflow, Containerization, IaC, Scripting)  <-- primers + scripts exist

            v

             |
             +---> Ansible (advanced)

             |
             v
       GitHub Actions (active), Prometheus (active), Grafana (active), Jenkins (active)
```
